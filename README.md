# 记忆库 · dsh-memory-vault

给我（AI）和你自己用的**长期对话记忆库**。它把每一轮对话自动归档成可检索的记忆，
再把「人设框架 + 相关记忆索引」在对话时分层注入，避免上下文被塞爆。

不是又一个聊天记录搜索——重点在**分层**：框架常驻、索引按需、原文留库。

## 五层结构

```
┌─ 事实（语义记忆 · facts.jsonl）
│   稳定的状态：称呼 / 名字 / 偏好 / 人设 / 项目目录
│   同槽位写入新值会自动让旧值失效 —— 改口之后不会同时召回两个矛盾答案
├─ 人设框架（常驻注入，每轮都在）
│   事实 + 手工编辑的投影：你的称呼、我的设定、性格、偏好、重要事件、目录
├─ 话题（按当前提问检索，动态注入）
│   同一件事的多轮合并成一个话题：时间跨度 · 轮数 · 事件类型 · 标题 · 代表 id
├─ 记忆索引（话题之外的零散单条）
│   时间 · 类型 · 摘要 · 关键词 · 对象实体 · 关联原因 · 条目 id
└─ 全文库（留在磁盘，用 memory_recall(id) 按需展开）
    你那句话的原话 + 我当时的完整回复
```

## 事实与冲突消解

「用户叫老王」是**状态**，「今天修了个 bug」是**事件**。混在一个池子里有两个后果：
稳定信息被流水淹没；用户改口后新旧值并存，检索时同时召回两个矛盾答案。

所以拆成两个库，事实层用**槽位**做冲突消解：

| 谓词类型 | 例子 | 行为 |
|---|---|---|
| 单值（nickname/name/calledBy/persona/role/model/language） | 称呼只能有一个 | 新值写入 → 旧值 `validUntil` 关闭、`supersededBy` 指向新值 |
| 多值（preference/personality/path/tag/skill/habit） | 偏好可以很多条 | 各自成槽位，只去重不覆盖 |
| 否定极性（`polarity: "-"`） | 「以后别叫我老王」 | 不参与注入，只用来让匹配的 (user,nickname,老王) 失效 |

```
"以后叫我老王"   → user/nickname = 老王
"叫我王哥"       → user/nickname = 王哥，老王那条自动失效
"以后别叫我老王" → 只让"老王"这条失效，不影响当前称呼
```

事实来源：模型总结时顺带抽取（prompt 里要求输出 `facts` 数组）、规则正则兜底、
以及 `memory_facts` 工具的手动断言。事实库同样是 log-structured 的 `facts.jsonl`。

## 人设框架自动生成

框架**不是**让人填表填出来的——没人会去填。它是从记忆里自己长出来的：

```
对话 → 每轮归档（顺带抽 facts）
     → 攒够 personaEvery 条，自动把最近 60 条记忆 + 现有事实喂给模型归纳
     → 归纳结果走同一条事实管道（冲突消解）
     → 注入时 composeFrame 投影成框架
```

归纳看的是**一段时间的整体**，所以能得出单轮看不出来的东西（长期偏好、稳定性格、反复出现的诉求）。
模型只被要求输出**有证据的**内容，宁少不错；`events` 只收里程碑（项目交付、重要决定、事故），最多 5 条。

面板「人设框架」页签顶部有「让 AI 重新归纳」按钮，随时手动触发一次；
其余时候它在你聊天过程中自己更新，右侧会显示上次归纳的时间。

手填的内容不会被覆盖：`profile.json` 是人工层，事实是自动层，投影时事实覆盖同名单值字段，
但手工填的空缺字段会保留（比如 `tone`、`notes`）。

### 三道防污染闸门

自动生成最大的风险是**自己污染自己**，所以归纳链路有三道闸：

**1. 事件只收长期约束**

模型很容易把「这次改了什么」当成里程碑。prompt 里给了明确判据（*这条信息三个月后还有用吗？*），
代码层再用 `isProcessEvent()` 兜底，识别 `自检 75/75 通过`、`修复了…bug`、`压缩 1034→80 行`、
`定位…改挂…修复` 这类工程流水。

**2. 框架回流拦截**

注入到系统提示的框架文本，有时会被会话摘要捕获，变成一条新记忆 ——
再喂回归纳就成了自我强化的正反馈（`记忆库面板挂载槽 shell.overlay` 就是这么进来的）。
`normalizeFact()` 与 `buildPersonaInput()` 都会识别并拒绝这类内容。

**3. 同一件事只留一条**

同一件事每次归纳的措辞都不同（`全程离线不联网` / `要求全程离线不联网`），
只比字符串会让它每轮追加一条。`sameEvent()` / `sameFactValue()` 按**共享实词**判重：

- 事件：共享 ≥2 个实词，或都提到「联网/离线」红线
- 多值事实：剥掉 `要求/希望/喜欢` 这类引导词后比较
- **路径不做模糊合并**：`D:\projects\mirror` 与它的 `\site` 子目录都是有效目录

实测：24 条堆积事件 → 3 条（17 条流水 + 4 条重复被清理），框架注入 1391 → 1212 字符。

## 话题聚合

「每轮一条流水」是记忆的反面：同一件事聊十二轮就散成十二条，检索时互相稀释。
所以按 **同一会话 + 相邻间隔 < 2 小时** 把轮次聚成话题：

```
1. 2026-10-22 10:25~13:09 · 4轮 · 决策 — alerts.log / 第三方应用测试 ｜ id=mv-xxx（含：…）
```

一行说清一件事，点开才是细节。话题标题优先取**实体**（项目名、文件名、域名），
没有实体才退回关键词——因为滑窗关键词会产出「地靶场」这类碎片，实体规则不会。

跨会话不合并是刻意的：误合并会把两件不相干的事糊在一起，比"分成两个话题"更难纠正。

## 记忆固化（consolidation）

一直追加的结果是库越来越吵：同一件事反复说，近似条目互相稀释；几个月前的琐碎轮次和昨天的决定同权竞争。
固化让库随时间变**密**而不是变**吵**，做三件事：

| 动作 | 触发条件 | 结果 |
|---|---|---|
| **合并** | 同话题内摘要相似度 ≥ 0.82（Jaccard） | 保留信息最全的一条，其余打 `archived` + `mergedInto` |
| **摘要** | 话题 ≥ 5 轮 且 结束 ≥ 3 天 | 压成一条 `digest`（时间跨度 · 轮数 · 关键结论），原始轮次打 `mergedInto` 指向它 |
| **归档** | ≥ 30 天 且 从没被召回 且 不是决策/身份/任务类 | 打 `archived`，退出自动召回 |

**全程可逆**：只打标签、只新增，原文永不删除。`archived` 条目不参与自动召回，
但 `memory_search`（手动）仍能搜到；`memory_recall(digestId)` 会连带展开被压缩的原始轮次要点。

摘要（digest）在检索里有 1.3× 权重——同样命中一次，一整段对话的信息量大于单轮。

触发方式：面板「固化」按钮、`POST /api/consolidate`、或定时任务（启动 1 分钟后一次，之后每 12 小时）。
CLI 可以离线跑：`node test/consolidate.mjs`（预览）/ `--apply`（执行）。

实测（2026-10-25，74 条记忆）：生成 5 条摘要、归档 46 条原始轮次 → 活跃区 74 → 33 条，再次运行计划全 0（幂等）。

## 存储压缩（compaction）

存档是 log-structured 的：每轮归档、每次总结更新、每次打标签、每次召回计数都追加一行。
所以 80 条记忆会积到 1034 行、4.7 MB——内容没变化，全是同一批条目被覆盖的中间版本。

压缩把操作流重写成「每条一行最终状态」：

```
条目：1034 行 → 80 行    4.7 MB → 355 KB（-92%）
事实：  31 行 → 17 行
耗时 6 ms，内容零丢失
```

安全措施：
- **原子替换**：Windows 上 `rename` 不能覆盖已存在文件，用「原文件→`.bak`、tmp→原名、删 `.bak`」的夹心写法，失败自动回滚
- **并发检测**：压缩期间文件大小变了（有人写过）就重来，不覆盖新数据
- **内容不变**：只丢被覆盖的中间版本，回放结果与压缩前完全一致（自检里有比对）

触发：启动 25 秒后自动判断（行数 > 条目数 × 2.5 且 > 200 行）、`POST /api/compact`、或 CLI
`node test/compact.mjs [--apply]`。

## 历史回填

`sessions/` 里已有的历史会话可以整个导进记忆库，不用重新聊一遍。

- **面板**：记忆页签 → 「导入历史」按钮（后台任务，带进度，重复导入自动跳过）
- **CLI**：`node test/backfill.mjs [会话数] [每会话轮数] [--dry]`

实现细节：会话日志是**多帧追加的 zstd**（一个 1.6MB 的文件里有 600+ 个独立帧），
所以按 zstd magic（`28 B5 2F FD`）切帧、逐帧解压再拼接，才能拿到完整事件流。
回填**不调用模型**——几百轮逐条总结会烧掉大量 token，规则摘要足够让它"能被检索到"。

## 记忆强度

每条记忆记 `hits`（被召回次数）。召回升权用**对数**（`1 + ln(1+hits) × 0.12`）：
反复被用到的记忆会略微靠前，但不会盖过内容相关性——否则库里只会剩下那几条老面孔。

计数在内存里累加，每 60 秒批量落盘一次，避免读一次写一次盘。

## 标签

- `test` —— 自检产生的条目，**默认不参与自动召回**，手动搜索仍可见
- `backfill` —— 历史回填来的，可信度低于实时记录
- `archived` —— 固化后归档，退出自动召回
- `digest` —— 话题摘要，检索时有 1.3× 权重

自动召回默认跳过 `test` 与 `archived`；要包含它们就显式传 `skipTags: []`。

## 自动沉淀

每轮对话结束时（`turn/end`，且结束原因为 `completed`）：

1. 归档本轮的用户话与我的回复
2. 规则层抽关键词、实体、事件类型、事实线索（零成本，永远会跑）
3. 若配置允许，再调模型做一次更好的摘要与事实抽取（失败自动降级为规则结果）

## 召回时的「思考延伸」

只按关键词匹配会漏掉「同一件事的其它轮次」。所以主命中之外还会带出：

- 同一会话内相邻的轮次
- 共享对象实体（同一个项目、同一个文件）的条目
- 同一话题的其它轮次

这些延伸命中的分数低于主命中，只是"顺带想起"，不会挤掉真正相关的结果。

## 三个入口

### 1. 侧栏面板（Web UI）

侧栏底部「记忆库」按钮 → 全屏面板，四个页签：

- **记忆** —— 搜索、按类型筛、展开原文、手动记一条、删除、导入历史、固化
- **人设框架** —— 查看/修正 AI 对你的认知；顶部「让 AI 重新归纳」
- **事实** —— 当前生效的稳定事实，可手动断言/失效
- **召回预览** —— 输入一句话，看这轮实际会注入什么（调试与信任都靠它）

### 2. 工具（我会自动用）

| 工具 | 用途 |
|---|---|
| `memory_search` | 检索记忆索引（返回摘要 + id，不含全文） |
| `memory_recall` | 按 id 取原文（摘要条目会连带展开被压缩的轮次要点） |
| `memory_note` | 手动记一条（用户明确要求记住、关键结论、重要决定） |
| `memory_profile` | 读/写人设框架 |
| `memory_facts` | 读/断言/失效稳定事实（改口时用它让旧值失效） |

## 数据在哪

默认 `$DSH_HOME/memory-vault`（DSH 状态根下的 `memory-vault` 目录）。
测试脚本按 `MV_DATA_DIR` → `$DSH_HOME/memory-vault` → `~/.dsh/memory-vault` 的顺序解析。

```
memory-vault/
  entries/2026-10.jsonl   情景记忆：按月分片，逐行追加（log-structured）
  facts.jsonl             语义记忆：事实的断言/失效/刷新操作流
  profile.json            手工维护的人设框架
  state.json              运行时状态
```

## 配置

`cordis.patch.yml` 里该插件的 config：

```yaml
  name: dsh-memory-vault
  config:
    dataDir: ''                 # 留空用 $DSH_HOME/memory-vault
    inject: true                # 关掉就只记录不注入
    maxInjectChars: 2600        # 注入预算（字符）
    autoSummarize: true         # 关掉就只用规则摘要，零模型调用
    summarizeProvider: ''       # 留空用当前默认模型
    summarizeModel: ''
    summarizeTimeoutMs: 25000
    maxEntries: 20000
    maxRecall: 8                # 单次最多带回的索引卡片数
    recordSubagents: false      # 是否记录子代理会话
    autoPersona: true           # 框架是否随对话自行生成
    personaEvery: 10            # 每新增多少条记忆触发一次框架归纳
    autoConsolidate: true       # 是否定时固化（合并/摘要/归档）
    consolidateMinAgeDays: 30   # 归档门槛：多少天以前的低价值条目
    consolidateDigestAgeDays: 3 # 摘要门槛：话题结束多少天后可以压成摘要
```

## 已验证 / 未验证

**已验证（自检 115/115 + 运行时探测）**

- 分词、停用词（含「你好」「可以」这类口语短段）、滑窗碎片过滤、实体抽取、事件类型判定、规则摘要
- 规则事实抽取：`叫我老王` → 断言、`别叫我老王` → 否定、`我喜欢X/不喜欢Y` → 偏好正负
- 冲突消解：同槽位新值让旧值失效、同值只刷新、否定只命中匹配值、多值谓词并存、不同 subject 互不干扰、已失效事实不参与判定
- 事实落盘与回放（断言 / 失效 / 刷新三种 op）、投影到框架时事实覆盖手工值、失效事实不进框架
- 存储回放、同 id 覆盖、删除、重启恢复、损坏行隔离、超限淘汰
- 中文/英文检索命中、不相干查询零误报、同会话延伸、共享对象延伸、空库不崩
- 召回计数累加与 drain、`test` 标签隔离（自动召回跳过、手动搜索可见）
- 模型总结的 JSON 解析（裸 JSON / 代码块 / 尾逗号）、失败降级、超时降级
- 注入渲染含框架与卡片、卡片单行、无内部细节泄漏、预算约束生效、空库返回空串
- 话题聚类（连续轮次合并、超时切分）、话题卡片、同话题多轮合并成一行
- 会话解析（只取正常完成的轮次、非真人来源不计入）、多帧 zstd 解码、回填端到端与去重
- 人设归纳：草稿过滤（空谓词/空值/非法日期）、草稿事实进冲突消解、时间线格式、条数上限、空库安全
- 归纳全链路：分片文本拼接解析、非 JSON 文本抛出可读错误、空记忆/空路由直接跳过
- 固化：Jaccard 相似度、同话题内并组（保留最长）、跨话题不合并、归档候选三重判据（旧+没召回+非决策类）
- 固化：digest 门槛（够大够旧）、摘要带跨度轮数要点、已固化话题不重复压、归档条目退出自动召回但手动可搜
- 压缩：追加流重写成一条一行（1034 → 80）、重开后条目与内容一致、事实库失效状态与替代关系保留
- 防污染：路径事实只认真路径、框架回流内容被拒、开发流水事件被过滤、同一件事按共享实词归并
- 框架合并：旧手填值与新事实语义去重（保留更简洁写法）、路径父子目录不被误合并
- 归纳容错：模型返回非 JSON / 空流时抛出可读错误（不再静默返回 null）、间歇故障自动重试 5 次（递增退避）
- **真实回填实测**：11 个历史会话 → 67 条记忆 / 13 个话题，已落盘
- **真实固化实测**：74 条 → 生成 5 条摘要 / 归档 46 条，活跃区降到 33 条，重跑计划全 0（幂等）
- **真实压缩实测**：4.7 MB → 355 KB（-92%），80 条记忆零丢失（唯一"缺失"的是本来就被 del 的测试条目）

## 已知短板 / 下一轮

已经解决的（见上文的实际实现）：

- ~~流水账~~ → 话题聚合：同会话连续轮次归并，检索单位从"某一轮"变成"某件事"
- ~~事实与叙事混库~~ → `facts.jsonl` 与 `entries/` 分开存，注入时事实走框架、事件走索引
- ~~没有冲突消解~~ → 槽位 + 否定极性，改口后旧值自动失效
- ~~历史会话没进库~~ → 回填（面板按钮 / CLI），实测 11 个会话 → 67 条
- ~~没有记忆固化~~ → 合并重复 / 话题压成摘要 / 归档低价值旧条目，实测活跃区 74 → 33 条
- ~~人设框架要手填~~ → 模型从记忆里归纳，改口自动生效
- ~~存储无限膨胀~~ → 压缩操作流，实测 -92%

还没做：

1. **纯字面检索**：`上次那个` 这类指代无法解析，需要结合最近几轮做 query expansion 或向量召回。
2. **摘要质量依赖规则**：digest 现在是"挑要点拼接"，没有真正的模型归纳；
   可考虑对高价值话题用模型精炼一次摘要。
3. **话题聚类按时间切**：时间相近但主题不同的对话会被并进同一个话题（实测：Wallpaper Engine 那段掺进了 pcl2start 渗透的内容）。
   应引入实体相似度做二次切分。
4. **事实抽取覆盖率低**：规则只认明确句式，模型调用失败时事实基本抽不到。
5. **归档条目仍保留全文**：压缩后每条约 4.4 KB（user + assistant 全文）。
   库涨到几千条时体积会到几十 MB，可以对 `archived` 条目截断正文字段（只留摘要 + 前 2000 字）。

## 开发

插件源码放在独立目录，profile 里用 **junction 链接**指过来，改完不用重装：

- `client.js`：改完刷新页面即可
- `index.js` 与 `lib/*.js`：属于 **Host 侧代码**，Node 已加载的模块不会重新执行 → **改完要重启 DSH**
- 自检：`node test/selftest.mjs`（115 项，纯离线，不碰真实库）
- 注入预览：`node test/preview.mjs "你那句话"`（读真实库 + 当前源码，不用重启就能看注入效果）
- 历史回填：`node test/backfill.mjs [会话数] [每会话轮数] [--dry]`
- 事实补抽：`node test/mine-facts.mjs [--dry]`（从已有记忆里抽稳定事实，按时间顺序消解冲突）
- 固化：`node test/consolidate.mjs [--apply]`
- 压缩：`node test/compact.mjs [--apply]`
- 清理工具：`clean-facts.mjs`（非路径/回流事实）、`clean-profile.mjs`（流水与重复事件）、`dedupe-facts.mjs`（同义偏好）、`dedupe-cross.mjs`（跨性格/偏好的重复）
